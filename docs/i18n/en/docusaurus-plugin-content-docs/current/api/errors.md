# Error Handling

This document describes the unified error response format, HTTP status codes, error code definitions, and the error handling mechanisms for both frontend and backend in the OptionDash API.

---

## Error Response Format

All API errors follow a unified JSON structure, generated by the `error_response()` function in `backend/utils/errors.py`:

```json
{
  "error": "ERROR_CODE",
  "message": "Human-readable error description",
  "timestamp": "2026-06-07T12:00:00Z",
  "details": {
    "ticker": "INVALID",
    "source": "yfinance",
    "reason": "Connection timeout"
  }
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `error` | string | Yes | Error code in UPPER_SNAKE_CASE |
| `message` | string | Yes | Error description with context information |
| `timestamp` | string | Yes | ISO 8601 UTC timestamp |
| `details` | object | No | Additional context containing specific error details |

---

## HTTP Status Codes

| Status Code | Meaning | Usage Scenario |
|-------------|---------|----------------|
| `200` | Success | Request completed normally |
| `400` | Bad Request | Ticker not in supported list, missing required parameters, invalid indicator name |
| `404` | Not Found | No data available (e.g., empty database) |
| `500` | Internal Server Error | Unexpected internal error |
| `502` | Bad Gateway | yfinance data fetching failed (upstream Yahoo Finance unavailable) |

---

## Error Code Reference

| Error Code | HTTP Status Code | Trigger Condition | Description |
|------------|-----------------|-------------------|-------------|
| `unsupported_ticker` | 400 | Requested ticker is not in the `SUPPORTED_TICKERS` list | Frontend should use `/api/tickers` to get the valid list |
| `no_valid_tickers` | 400 | All tickers received by the Comparison API are invalid | Check the `tickers` parameter format |
| `invalid_indicators` | 400 | All indicator names received by the Macro History API are invalid | See Macro API documentation for valid values |
| `data_source_error` | 502 | yfinance call failed | May be a network issue or Yahoo Finance service unavailable |
| `no_data` | 404 | No data available for the specified ticker and endpoint | Data source may be unavailable or ticker has no options data |
| `INTERNAL_ERROR` | 500 | Unexpected server exception | Usually accompanied by exception stack traces in server logs |

## Backend Error Handling Functions

`backend/utils/errors.py` provides three convenience error functions used uniformly across all API blueprints:

### error_response()

```python
def error_response(error_code: str, message: str, status: int = 500, details: dict | None = None)
```

General-purpose error response function. Automatically logs the error and returns a formatted JSON response.

| Parameter | Type | Description |
|-----------|------|-------------|
| `error_code` | string | Error code |
| `message` | string | Error description |
| `status` | int | HTTP status code, defaults to 500 |
| `details` | dict | Optional, additional context |

### ticker_not_supported()

```python
def ticker_not_supported(ticker: str) -> tuple
```

Specialized error for unsupported tickers. Returns HTTP 400 with `details` containing the requested ticker and the list of supported tickers.

**Response Example:**

```json
{
  "error": "unsupported_ticker",
  "message": "Ticker 'INVALID' is not supported. Supported: SPY, QQQ, IWM, TLT, XLF",
  "timestamp": "2026-06-07T12:00:00Z",
  "details": {
    "ticker": "INVALID",
    "supported": ["SPY", "QQQ", "IWM", "TLT", "XLF"]
  }
}
```

### data_source_error()

```python
def data_source_error(ticker: str, source: str, original_error: Exception) -> tuple
```

Specialized error for data source fetch failures. Returns HTTP 502 with `details` containing the ticker, data source name, and the original exception message.

**Response Example:**

```json
{
  "error": "data_source_error",
  "message": "Failed to fetch dashboard_summary for SPY: HTTPSConnectionPool timeout",
  "timestamp": "2026-06-07T12:00:00Z",
  "details": {
    "ticker": "SPY",
    "source": "dashboard_summary",
    "reason": "HTTPSConnectionPool(host='query1.finance.yahoo.com', port=443): Read timed out"
  }
}
```

### no_data_available()

```python
def no_data_available(ticker: str, endpoint: str) -> tuple
```

Specialized error for when no data is available. Returns HTTP 404.

**Response Example:**

```json
{
  "error": "no_data",
  "message": "No data available for SPY at max-pain-vs-price. The data source may be unavailable or the ticker may have no options data.",
  "timestamp": "2026-06-07T12:00:00Z",
  "details": {
    "ticker": "SPY"
  }
}
```

## Frontend Error Handling

The frontend uses a multi-layer error handling strategy:

### API Client Interceptor

The frontend uses an axios instance (`apiClient`) for all API requests. Interceptors catch HTTP errors and handle them uniformly:

- Logs errors to the console
- Extracts error messages for UI display
- Distinguishes between network errors and server errors

### Module-Level Error Display

Each data module handles error states independently:

- When an error occurs, an Alert component is displayed with the error message and a "Retry" button
- Clicking the retry button re-sends the request
- Some modules support automatic fallback (e.g., using the `FALLBACK_TICKERS` constant when `/api/tickers` fails)

### ErrorBoundary Component

The React ErrorBoundary catches rendering exceptions in the component tree:

- Prevents the entire page from crashing due to abnormal data formats
- Displays a user-friendly error message page
- Provides a "Refresh Page" recovery action

### Polling Fault Tolerance

When background auto-refresh (every 5 minutes) encounters an error:

- The polling cycle is not interrupted
- The last successfully fetched data continues to be displayed
- Errors are silently logged without triggering alerts

## Common Error Troubleshooting

### 400: unsupported_ticker

**Cause:** The requested ticker symbol is not in the `SUPPORTED_TICKERS` environment variable.

**Solution:**
1. Call `GET /api/tickers` to get the list of valid tickers
2. To add a new ticker, set the environment variable `SUPPORTED_TICKERS=SPY,QQQ,IWM,TLT,XLF,AAPL` and restart the service

### 502: data_source_error

**Cause:** yfinance cannot fetch data from Yahoo Finance.

**Possible Causes and Solutions:**
1. **Network Issues** - Check the server's network connection
2. **Yahoo Finance Rate Limiting** - The system has a built-in rate limiter (default 2 RPS). If still being rate-limited, adjust `RATE_LIMIT_RPS`
3. **Market Closed** - Data may be delayed during market holidays
4. **Ticker Has No Options** - Confirm the ticker has an active options market

### Empty Response Array

**Cause:** The Historical API returns an empty array.

**Solution:** There are no historical snapshots in the database yet. Wait for the daily 16:30 ET automatic collection, or call `POST /api/historical/snapshot` to trigger manually.
